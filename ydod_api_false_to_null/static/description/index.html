API False to NULL Converter at work

Overview

Odoo represents empty Char, Text, Many2one, Date, Selection, and other non-Boolean fields as false in ORM read results. That value can violate the expected types in TypeScript, React, Vue, Flutter, Swift, Kotlin, and other API clients. This lightweight developer utility converts those empty values to Python None, serialized as JSON null, without changing actual Boolean fields.

Use it for mobile apps, single-page applications, and middleware calling Odoo JSON-RPC or REST controllers that use read() or search_read(). Conversion is opt-in per request or can be enabled globally. The module adds no business models, menus, or database schema.

Key Highlights

Smart field typing

Uses each model's field metadata to distinguish Boolean values from empty values of other types.

Per-request control

Pass api_false_to_null in request context and leave standard client requests unchanged.

Optional global mode

Administrators can activate conversion for all reads with one System Parameter.

Nested relations

Recursively handles nested dictionaries and lists using related models' field metadata.

Boolean values preserved

True and False on Boolean fields remain Boolean values and are never rewritten as null.

Lightweight integration

No external packages, custom models, or database schema changes are introduced.

Features in Detail

Read and search_read responses

When enabled, results from read() and search_read() are processed after the ORM fetch. Empty non-Boolean values such as Char, Text, Many2one, Date, Datetime, Selection, and Binary become None. Fields with actual values are returned as-is.

Context toggle for API requests

Set context={'api_false_to_null': True} on the API call to enable conversion for that request. Set it to False to explicitly disable conversion, including when global mode is enabled. Requests without this key retain normal Odoo values unless the global parameter is on.

Global System Parameter

In Settings > Technical > System Parameters, set ydod_api_false_to_null.enabled to True. Odoo 20's typed configuration API reads this value as a Boolean. The explicit request context takes precedence over this global setting.

Nested relational records

The conversion follows nested dictionaries and lists in relational read results, including Many2one records and One2many or Many2many collections. It checks each nested record against the related model's own field definitions, so Boolean values on child records are preserved too.

How to Use

  1. Install API False to NULL Converter from the Apps menu or your normal module deployment process.
  2. No setup is needed for selective use; the converter is available immediately after installation.
  3. For a specific JSON-RPC call, include api_false_to_null: true in the request context.
  4. To enable it globally, open Settings > Technical > System Parameters as an administrator and set ydod_api_false_to_null.enabled to True.
  5. Call read() or search_read() and check that empty non-Boolean values are null in JSON while Boolean values remain true or false.
  6. For REST controllers, pass the context through the controller's existing ORM call; the module does not add a separate REST endpoint.

FAQ

Does this module need configuration?

No. Use the request context immediately, or optionally turn on global mode with the System Parameter.

Who can change the global setting?

System administrators with access to Technical Settings can manage the parameter. Per-request use needs no settings change.

Does it change the database or work across companies?

It creates no business tables or company-specific records. The global parameter applies to the database; each conversion still uses the current request's model and context.

Will Boolean fields or normal web-client requests change?

No. Boolean values are preserved. Without the context key and with global mode disabled, reads retain Odoo's standard values.

What happens when the module is uninstalled?

The runtime conversion hooks stop loading with the module. The setting is an ir.config_parameter entry and can be removed from System Parameters if desired.
