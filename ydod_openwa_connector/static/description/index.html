Overview

Many SMEs, resellers and integrators already run OpenWA (whatsapp-web.js / Baileys) on their own server to talk to customers on WhatsApp. Without a connector, every conversation lives on a phone, outside the CRM, with no history and no control over who sends what.

OpenWA Connector Core links Odoo Community to your OpenWA server. Administrators configure the connection and pair numbers by scanning a QR code inside Odoo. Users send text and files from any contact, customer replies arrive as conversations in Discuss for the team that owns the number, and every message is logged with its sent, delivered and read status. Built for Indonesian and other SMEs that want WhatsApp in Odoo without the official WhatsApp Business API, and designed as a provider for ydod_notify_gateway.

Features in Detail

Connection settings

In Settings → WhatsApp administrators enter the OpenWA Base URL, X-API-Key, Request Timeout, Webhook HMAC Secret, Country Code (62 by default), Default Session and Fallback User. The Test Connection button calls GET /api/health and shows the server version, or the HTTP status and error text. The API key and secret are stored as system parameters visible only to Settings administrators.

WhatsApp sessions and QR pairing

  • WhatsApp → Configuration → Sessions: one session per WhatsApp number, with kanban, list and form views.
  • Header buttons Create on Server, Start, Refresh Status / QR and Stop; Start also registers the signed webhook on the OpenWA server.
  • Status Disconnected, Pairing, Connected or Failed, with the pairing QR image while pairing and the last error in a red banner.
  • A warning banner explains the ban risk of unofficial WhatsApp clients.

Send WhatsApp wizard

The Send WhatsApp button on contacts (also in the Action menu) opens a dialog with the contact, a preview of the normalised number, the session, the message and an optional attachment of the record. Numbers from the phone field are cleaned of spaces, dashes, dots and "+", a leading 0 becomes the country code and @c.us is appended; invalid numbers are refused before any call. Successful messages are posted as a note in the contact's chatter and in the related document.

Incoming messages in Discuss

  • Each WhatsApp contact gets a private Discuss conversation named WhatsApp: contact, shared with the session's Discuss Inbox Users.
  • Without inbox users, the users whose own phone matches the session number receive the chat, then the Fallback User.
  • Replying in that Discuss conversation sends the answer back to the customer over WhatsApp; failures are shown in the conversation.

Signed webhook

The public endpoint /openwa/webhook/<token> checks the X-OpenWA-Signature HMAC-SHA256 header and answers 401 on a missing or wrong signature and 404 on an unknown token. It handles message.received, message status (sent, delivered, read, failed) and session.status. Re-delivered events never create duplicates.

Message log

WhatsApp → Messages lists every message with direction, contact, number, body, session, status badge and error. Filters Failed, Today, Incoming, Outgoing and My Messages, group-bys by Status, Session, Contact, Direction and Date, and a Messages smart button on contacts and sessions.

Safety and pacing

  • Dedicated Number Confirmed must be ticked before a session can send.
  • WhatsApp Opt-in checkbox on contacts with its date, and a Require Opt-in setting that blocks other contacts.
  • Minimum Delay (s) between messages and Hourly Cap per session.

How to Use

  1. Install the module from Apps. It depends only on Base, Discuss (mail) and Web.
  2. Go to Settings → WhatsApp, enter the OpenWA base URL, X-API-Key, webhook secret, timeout and country code, and click Test Connection.
  3. Give users access in Settings → Users: WhatsApp (OpenWA) / User to send and see their own messages, Manager to manage sessions and all logs. Settings administrators are managers automatically.
  4. Open WhatsApp → Configuration → Sessions, create a session, tick Dedicated Number Confirmed, add the Discuss Inbox Users and click Create on Server then Start.
  5. Scan the QR code with WhatsApp (Linked Devices) and click Refresh Status / QR until the status is Connected. Optionally set it as Default Session in Settings.
  6. On a contact with a phone number, click Send WhatsApp, write the message, optionally pick an attachment and click Send.
  7. Answer customer replies in Discuss and follow delivery in WhatsApp → Messages with the Failed and Today filters.

FAQ

Do I need the official WhatsApp Business API?

No. The module talks to your own OpenWA server (whatsapp-web.js / Baileys). You need a running OpenWA instance reachable from Odoo, and Odoo must be reachable from OpenWA for the webhook.

Can my number be banned?

OpenWA uses an unofficial client, so WhatsApp can ban numbers that send bulk or unsolicited messages. Use a dedicated number, enable Require Opt-in and keep the minimum delay and hourly cap.

Who can see which messages?

OpenWA Users see only their own messages and can read the sessions of their companies; Managers see all sessions and logs of their companies; only Settings administrators see the API key and webhook secret.

Does it work with several companies?

Yes. Each session belongs to a company, and access rules limit sessions and logs to the companies of the user.

Where do replies from unknown numbers go?

They open a Discuss conversation named after the number for the session's inbox users, or the Fallback User when the session has none.

What happens when I uninstall?

Sessions, the message log and the opt-in fields are removed. Discuss conversations and chatter notes remain as regular messages; your OpenWA server is not changed.
