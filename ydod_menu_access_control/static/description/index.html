Overview

Standard Odoo shows a menu to every user who has read access to its model. In real companies that is often too much: a warehouse clerk does not need the Configuration menu, an intern should not browse Reporting, and a partner's accountant should only see a handful of entries. Changing access groups to achieve this is slow and risky.

yDoD Menu Access Control adds a simple layer of menu restrictions. Each restriction says: this menu is hidden for this user (or this group) in this company. The web client menu is filtered when it loads, so hidden menus and their sub-menus simply disappear. Access rights stay untouched, and system administrators always see everything.

It is built for system administrators and IT managers of Odoo 16 Community or Enterprise who need fine-grained control over which menus each user or group can see, without writing code or inventing new security groups.

Features in Detail

Central Menu Restrictions screen

Open Settings → Users & Companies → Menu Restrictions. The list shows the Menu, User, Group, Company and the Inherited from Parent flag of every rule. Filters User Rules, Group Rules, Defined Manually and Inherited from Parent plus group-bys by Menu, User, Group or Company make large setups easy to audit. The form view asks for the menu, the company and the target: either a user or a group, never both.

User-wise hiding from the user form

  • The user form gets a Menu Restrictions tab with an editable list: add a line, pick the menu, done.
  • A Hidden Menus smart button shows how many menus are hidden and opens them in the central list.
  • The hidden menu and all of its sub-menus disappear the next time the user loads the web client.

Group-wise hiding from the menu form

In Settings → Technical → User Interface → Menu Items, every menu form gets a Restrict Access tab. Add a Group (or a single User) and a Company in the editable list and all members of that group stop seeing the menu. Rules created from the user form appear here too, and vice versa, because both tabs show the same restriction records.

Copy Hidden Menus wizard

  • Click Copy Hidden Menus in the Menu Restrictions tab of a user, or use the Action menu of the user form.
  • Choose the users to Copy To; the wizard shows how many hidden menus will be copied.
  • Tick Replace Existing Restrictions to wipe the targets' current rules first; otherwise existing rules are kept and duplicates are skipped.

Cascade to Sub-Menus

Press Cascade to Sub-Menus in the Restrict Access tab, or select several menus in the Menu Items list and run the Cascade Restrictions to Sub-Menus action. Every restriction of the selected menus is copied to all of their descendants with the same user or group and company. The copies are flagged Inherited from Parent and existing rules are never duplicated.

Roles and administrator bypass

  • Administration / Settings users have full control over all rules and always see every menu.
  • The new Menu Access Manager role can create, edit and delete rules for its own companies only, and is itself subject to the rules.
  • Other users never see the restriction records; they only notice that menus are gone.

How to Use

  1. Install the module from Apps. No extra configuration is required.
  2. Assign roles: in Settings → Users & Companies → Users, open the Access Rights tab and set Menu Access Control to Menu Access Manager for trusted non-administrators. They also need Administration: Access Rights to open the Settings app itself. Administrators need nothing extra.
  3. Hide a menu for a user: open the user, go to the Menu Restrictions tab, add a line with the menu and save.
  4. Hide a menu for a group: activate developer mode, open Settings → Technical → User Interface → Menu Items, open the menu, add the group in the Restrict Access tab and save.
  5. Hide a whole branch: hiding a parent menu already hides its sub-menus; use Cascade to Sub-Menus when you also want explicit rules on every child.
  6. Roll out to a team: configure one user, then use Copy Hidden Menus to apply the same rules to colleagues.
  7. Review: Settings → Users & Companies → Menu Restrictions shows and filters every rule. Ask affected users to refresh their browser to see the change.

FAQ

Does hiding a menu remove the user's access rights?

No. The module only filters the menu tree shown in the web client. Access rights, record rules and direct links to records keep working exactly as before. Use it for a cleaner, role-focused interface, not as a replacement for security groups.

Can I accidentally lock out the administrator?

No. Users in the Administration / Settings group bypass all restrictions, even if a rule targets them or one of their groups.

How does it behave in a multi-company database?

Every rule belongs to a company and only applies to users who have access to that company. Menu Access Managers can only create and see rules of their own companies; administrators manage all of them.

A user still sees a menu I just hid. Why?

The menu tree is loaded once per session. The server cache is refreshed automatically; the user only needs to reload the browser page.

What happens to my data when I uninstall?

All menu restriction records are removed and every user sees the standard menus again. No other data is affected.

Does it depend on other paid or third-party modules?

No. It only depends on the standard base and web modules of Odoo 16 Community and works on Enterprise as well.
