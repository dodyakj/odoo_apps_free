Replenishment Approval Workflow

Add a manager sign-off step between a triggered reordering rule and the resulting purchase order, so automatic replenishment never commits your business to a vendor without human review.

Key Features

☑

"Require Approval" on Reordering Rules

A simple checkbox on each orderpoint flags which reordering rules need a human decision before buying.

📋

Pending Requests Instead of RFQs

When a flagged orderpoint triggers, it creates a Replenishment Request instead of generating an RFQ directly.

✓

Approve / Reject Actions

Approving runs the standard procurement flow and generates the normal purchase order. Rejecting always requires a documented reason.

🔍

Dedicated List & Kanban View

Browse pending requests filtered by warehouse or responsible buyer, with clear status badges and group-bys.

🔔

Activity Notifications

The responsible buyer automatically gets a to-do activity the moment a new request needs their review.

📄

Full Audit Trail

Every decision keeps who decided, when, and -for rejections- why, directly on the record's chatter.

How to Use

1

Open a Reordering Rule and tick Require Approval, then set the Responsible Buyer.

2

When the rule triggers, a Replenishment Request is created and the buyer is notified.

3

Open the request from Purchase → Orders → Replenishment Requests.

4

Click Approve to generate the purchase order, or Reject with a reason.
