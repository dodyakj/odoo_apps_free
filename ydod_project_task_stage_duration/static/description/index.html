Why Track Stage Durations?

In high-velocity teams, tasks easily get stranded in code review, QA testing, or client approval without anyone noticing. This module provides complete visibility into cycle times without needing expensive Enterprise upgrades.

⏰
Automated Duration Logging

Logs exact entry date, exit date, responsible user, and calculated elapsed duration in hours and 24-hour days on every stage transition.

⚠
Smart Bottleneck Alerts

Configure maximum duration thresholds in hours on any stage. When tasks exceed the threshold, prominent red warning tags immediately highlight the blocker.

👁
Live Kanban Badges

Dynamic time-in-stage pills appear right on Kanban cards and task form headers, giving team members instant awareness of task freshness.

📄
Stage History Audit Tab

A dedicated "Stage History" tab on each task records the complete chronological journey from inception to completion, showing who moved what and when.

📊
Pivot & Graph Reports

Access the "Stage Duration Analysis" reporting menu to aggregate average cycle times across stages, projects, and users with interactive pivot tables and bar charts.

💬
Automated Chatter Notes

Every stage change posts a clean internal note into the task chatter logging the previous stage and the precise duration spent before transitioning.

How It Works in 4 Simple Steps

Designed for seamless, zero-friction integration into your existing workflow.

Step 1
Set Stage Targets

Open Project > Configuration > Task Stages and enter the maximum allowed hours (e.g. 24h for In Progress, 8h for Review).

Step 2
Work on Tasks

Create and update tasks as usual. The module automatically initializes entry timestamps and tracks ongoing time.

Step 3
Spot Bottlenecks

Kanban cards highlight in red when tasks exceed target duration. Filter tasks using the "Bottleneck Tasks" search filter.

Step 4
Analyze Cycle Times

Review the Stage History tab on tasks or open Reporting > Stage Duration Analysis to identify organizational delays.
